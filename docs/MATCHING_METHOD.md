# How the smart features work (and fail)

All rules; no ML, no external service. Numbers: `make evaluate` → MATCHING_EVAL.md (synthetic labelled set).

| Feature | Problem | Rule / algorithm | In → out | Why this method | Known failures | When unsure |
|---|---|---|---|---|---|---|
| **Name → institution** (`matching.suggest_institution`) | Complaints name colleges loosely ("Kaveri Inst. of Engg & Tech") | Normalise (case, punctuation, Inst./Engg/Tech/&, filler words) → RapidFuzz token-set on the whole name **and** on distinctive words only (generic words like Institute/College removed, misspellings of them too); score = the lower one; +5 if the city is typed, -20 if another institution's city is typed; an AICTE ID in the text wins | typed text + institution list → institution, score, reasons | Explainable, no training data needed, handles abbreviations and look-alikes ("Kaveri College of Pharmacy" ≠ "Kaveri Institute of Engineering") | Heavy misspelling of the distinctive word plus abbreviations (23/24 found); only generic words typed (never matched, by design); acronyms unless saved as an alias | Two candidates within 5 points → no suggestion, officer picks. Below 80 → no suggestion. Nothing links without "Confirm match"; confirmed spellings become aliases |
| **Overlap score** (`matching.pair_score`) | Two units act on the same college/issue without knowing | Only open cases, different units. Institution 0-40 (ID on both 40; name match 34); issue 0-40 (same category 15 or related category 10; TF-IDF cosine on descriptions up to 15); time 0-20 (linear over the 180-day window). Outside the window: capped at 50. Alert at 65 | two cases → score, 3 parts, reasons, missing evidence | Each point has a sentence a judge can check; weights simple enough to argue about | Same institution, different words *and* unrelated categories score lower (by design, they are less likely duplicates). Synthetic text is cleaner than real complaints | Score is a ranking signal, not a probability. Coordinator decides: lead unit, link, merge or dismiss with reason. Dismissed pairs are not raised again |
| **Conflict guard** (`workflow.record_action`) | One unit issues a show-cause while another is mid-way | Before a *regulatory* action (inspection, show-cause, penalty, intake cut, withdrawal), list other units' open cases on the same institution; API returns 409 until a reason (≥10 chars) is given | case + action → warning list / acknowledgement | Humans decide; nothing is blocked | Misses institutions not yet matched (typed-only cases still count via the suggestion) | Always asks when in doubt; reason logged, other unit and Coordinator notified |
| **SLA alerts + ladder** (`sla.run_daily`) | Cases go late silently | % of SLA used: alerts at 75/90/100 (due day), then overdue; overdue 3/10/25 days → Unit Head / Coordinator / Management | cases + date → in-app messages, one digest email per person | Transparent, Admin-editable | SLA counts calendar days, not working days | Every step is a case event and an audit entry |
| **Suggested next step** (`workflow.recommend`) | New officers don't know what's next | 9 ordered rules R1-R9 (pending transfer, open overlap, unassigned, overdue, reply received, no reply in 15 days, …) with evidence, incl. the last similar disposed case | case → action + evidence | Explainable; "Use this" pre-fills, never auto-acts | Rules are generic, not tuned on real files | Whether the officer followed it is stored on the action, so acceptance can be measured |

**Evaluation summary (synthetic):** names hybrid@80 precision 1.00 / recall 0.96 (exact match 1.00 / 0.34; plain ratio 0.95 / 0.62). Pairs @65 precision 0.99 / recall 0.98 / FPR 0.00; without text similarity recall falls to 0.81; with topic-word points precision falls to 0.94, so they are off. **Limit:** we built the test set; real data will score lower until tuned on labelled AICTE cases.
